① 原始 log

使用者從互動小說平台匯出的原始紀錄——時間戳、說話者、內文擠成一串未結構化的文字。這是 pipeline 的原料。

sample_log.txt

            

            
注意這一坨文字沒辦法直接依時間查詢、也不好核對範圍——所以下一步要先把它切成一則一則的記錄。

          


          
          

            

              
② 解析

              
parser 依每則的時間戳與說話者，把整串文字切成一則一則的 turn，並掛上 log time 當索引。這樣一個 run 才能依時間區段把要分析的範圍撈出來。

            

            

            

            
確認範圍此頁只是標示這個 run 撈到的區段（上方時間窗），不提供選取；範圍由後端 run 的時間區段決定。點任一則展開看內文。

          


          
          

            

              
③ Pipeline 執行

              
把結構化 log 與角色設定 context 組裝成四組 prompt，各自帶自己的 system instruction，批次送給 Gemini，回填結果。

            

            

            
示意本頁為靜態 demo，不會真的呼叫 API；真實執行由後端 run_pipeline 完成。prompt 以純文字檔外部化，措辭調整不需改程式。

          


          
          

            

              
④ 四種輸出

              
同一段劇情，四種分析視角。形狀刻意不同——條列、時間軸、關係結構、單段摘要——各自服務不同的閱讀需求。

            

            

            

            
✓ eval結果存入 DB 後，由解耦的 length_check 直接讀取檢查，不重呼叫 LLM——eval 是開發者品質工具，不佔用 API 額度。
